# تاجر — نسخة كاملة لـ GitHub Pages

برنامج عربي لإدارة استيراد الملابس وبيعها بالجملة، يعمل على الهاتف والحاسوب دون خادم أو تسجيل دخول.

**الملف index.html في جذر الحزمة جاهز للنشر. لا تحتاج إلى تثبيت Node.js أو تشغيل أوامر لبداية الاستخدام على GitHub Pages.**

## النشر الأسرع

1. فك ضغط الحزمة على جهازك.
2. أنشئ مستودعًا على GitHub، مثل tajer-wholesale. إذا كنت تستخدم GitHub Free، تكون GitHub Pages متاحة للمستودعات العامة.
3. ارفع محتويات الحزمة إلى المستودع. يجب أن يكون index.html في جذر المستودع مباشرة، لا داخل مجلد إضافي. لا ترفع ملف ZIP نفسه بدل الملفات.
4. افتح Settings ثم Pages.
5. في Source اختر Deploy from a branch، ثم اختر main والمجلد /(root)، واضغط Save.
6. انتظر اكتمال النشر، ثم افتح رابط الموقع الذي يعرضه GitHub. أرسل هذا الرابط لصديقك ليجرب البرنامج.

الملفات الأساسية للتشغيل هي index.html وsw.js وmanifest.webmanifest وfavicon.svg وicon-192.png وicon-512.png و.nojekyll. يحتوي index.html على الشفرة والتصميم محليًا دون مكتبات من CDN.

دليل GitHub الرسمي:
https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## الحفظ ونقل البيانات

- البيانات محفوظة في متصفح الجهاز الحالي باستخدام IndexedDB.
- لا تُرفع سجلاتك المالية أو بيانات زبائنك إلى GitHub، ولا تحتاج إلى حساب ChatGPT.
- كل متصفح وجهاز يحتفظ ببياناته. لا توجد مزامنة تلقائية بين الهاتف والحاسوب.
- لنقل البيانات اختر «نسخة احتياطية»، وانقل ملف JSON إلى الجهاز الآخر، ثم افتح «استعادة ونقل البيانات» واختر الملف وراجع محتوياته واعتمد الاستعادة.
- الاستعادة تستبدل بيانات الجهاز المستهدف؛ لا تدمج تغييرات جهازين تلقائيًا. اعتمد جهازًا أساسيًا وأحدث نسخة عند النقل.
- يُحتفظ بلقطة داخلية قبل الاستعادة وبعض العمليات المهمة، ويمكن معاينتها واستعادتها من شاشة النسخ الاحتياطية.
- يدعم البرنامج نسخ JSON الاحتياطية الصادرة من النسخة السابقة المنشورة.
- حذف بيانات المتصفح أو استخدام نافذة خاصة قد يزيل البيانات المحلية. احتفظ بنسخة JSON خارج المتصفح بانتظام؛ فاللقطات الداخلية ليست بديلًا عن ذلك.
- تغيير عنوان المستودع أو اسم مجلده ينشئ مساحة تخزين مختلفة؛ انقل نسختك الاحتياطية عند الانتقال.

## الاستخدام اليومي

1. اختر «حاوية جديدة» وسجّل المورد والعملة وسعر التحويل للشيكل.
2. أضف الموديلات يدويًا أو استورد ملف Excel .xlsx أو CSV / TSV. يُقرأ أول جدول عمل في Excel، ويمكن مطابقة الأعمدة يدويًا قبل الاستيراد.
3. أضف مصاريف الصين والشحن البحري والتخليص والنقل حتى المستودع.
4. وزّع كل مصروف بالقيمة أو عدد القطع أو الحجم أو الوزن، أو خصّصه لصنف محدد.
5. راجع تكلفة القطعة الواصلة وسعر البيع والربح المتوقع. يمكن حساب أسعار مقترحة بهامش من سعر البيع.
6. عند الوصول، طابق العدد السليم والتالف وفروقات الجرد واعتمد الاستلام.
7. سجّل المبيعات والدفعات. المخزون القادم لا يُتاح للبيع قبل الاستلام.
8. بعد تأكيد جميع المصاريف، اعتمد تكلفة الحاوية النهائية.

تتضمن الواجهات الأربع الحاويات، والبيع السريع، والمخزون، والحسابات والتقارير. وتتوفر الملاحظات والطباعة وتصدير CSV وكشوف الحساب وإلغاء الفاتورة المسجلة بالخطأ مع تسوية مدفوعها.

## الحسابات

- تكلفة الوصول تشمل شراء البضاعة والمصاريف المرتبطة بوصولها إلى المستودع.
- تُوزّع المصاريف المشتركة حتى آخر أغورة، وتبقى دقة تكلفة الوحدة كاملة قبل تقريب العرض.
- عند فروقات الاستلام، تُحمّل تكلفة الصنف على القطع السليمة المستلمة. الصنف دون قطع سليمة يظهر كخسارة مخزون في التقرير.
- البيع يستخدم أقدم الدفعات المستلمة المتاحة، ويحتفظ بمرجع كل دفعة.
- أرباح الدفعات التي لم تعتمد تكلفتها نهائيًا تظل تقديرية وتتحدث عند استكمال المصاريف.
- الربح الإجمالي = صافي البيع بعد الخصم ناقص تكلفة البضاعة المباعة.
- الربح بعد المصاريف يخصم التوصيل والمصاريف العامة وخسائر المخزون المسجلة. لا تخصم مصروف الوصول مرة ثانية.
- أسعار الصرف تُدخل يدويًا، ولا يجري جلب أسعار سوق آلية.

## العمل دون إنترنت

بعد زيارة الرابط عبر HTTPS لأول مرة واكتمال تحميله، يمكن فتح النسخة المحفوظة والعمل على البيانات المحلية دون إنترنت في المتصفحات الداعمة. يمكن إضافته إلى الشاشة الرئيسية من قائمة المتصفح.

## المثال التجريبي

اختر «استعراض مثال تجريبي» لتجربة البرنامج دون تعديل بياناتك الحقيقية. داخل المثال يمكن تجربة كشف Excel نموذجي من شاشة استيراد الأصناف.

## تطوير الكود اختياريًا

الكود الأصلي داخل src، والاختبارات داخل tests. يتطلب التطوير Node.js 22.13 أو أحدث؛ يفضل Node.js 24.

~~~sh
npm install
npm run check
npm run build
npm test
~~~

تُنتج عملية البناء نسخة مستقلة داخل dist وتحدث ملفات النشر في جذر المشروع. عند تعديل الكود أعد البناء وارفع ملفات النشر المحدثة إلى GitHub.

لتشغيل نسخة التطوير:

~~~sh
npm run develop
~~~

هذه حزمة مستقلة لـ GitHub Pages. النسخة السابقة على الاستضافة الأخرى لا تتغير عند استخدام هذه الحزمة.
